# Layra 穿搭助手 · 下一阶段开发计划（第二版）

> 根据需求确认更新。待确认细节后开发。

## 一、本次要开发的 4 个功能

### 功能 1：收藏搭配（生成效果图后保存）
- **场景**：用户生成试穿效果图后，觉得这套不错，点「保存」把这套搭配收藏起来。
- **开发**：
  1. 新增数据表 `saved_outfits`（收藏的搭配：title、scene、itemIds、createdAt）；
  2. 后端接口：保存 / 列表 / 删除；
  3. 前端：试穿效果图弹窗里加「保存这套搭配」按钮；个人中心「我的搭配」读真实收藏、可删除、可再次试穿。

### 功能 2：城市定位 + 当地天气自动查询
- **场景**：打开应用自动定位到用户所在城市，自动查当地天气用于穿搭推荐。
- **开发**：
  1. 进入应用自动发起定位（geolocation），失败则回退到默认城市；
  2. 城市选择持久化（记住用户上次选的城市）；
  3. 天气自动查询（复用现有 weather 接口，传经纬度/城市）。

### 功能 3：聊天式调整（对搭配区域改单品，与衣柜联动）
- **场景**：看到一套搭配后，用户说"把鞋子换成白色运动鞋"或"换件外套"，AI 理解要改哪个区域，**从用户衣柜里**找替换单品，实时更新搭配。
- **开发**：
  1. 后端新增"调整搭配"接口：输入当前搭配 + 用户指令，AI 判断要改哪个区域（上衣/下装/鞋/配饰），从衣柜里选出替换单品，返回新搭配；
  2. 前端：聊天框支持"换 X"指令，替换后更新搭配展示（并可重新生成试穿图）。

### 功能 4：历史记录对话留存，可回看
- **场景**：用户每次推荐/调整的对话和搭配结果都保存下来，侧边栏「近期记录」可回看。
- **开发**：
  1. 新增数据表 `chat_history`（历史对话/搭配记录）；
  2. 后端接口：保存记录 / 历史列表；
  3. 前端：侧边栏「近期记录」读真实历史，点击可回看那次搭配。

## 二、技术说明

- 复用现有数据库层（MySQL/本地 SQLite 双模式）+ owner 匿名隔离；
- 功能 3 复用现有搭配引擎（outfit-engine）做替换单品筛选；
- 试穿、商品图、识别等已稳定能力不动，只在上面叠加新功能。

## 三、需要你确认的细节

1. **功能 3 的替换方式**：用户说"换双鞋"时，是——
   - (a) AI 自动从衣柜挑一双最合适的鞋替换？还是
   - (b) 弹出衣柜里所有鞋子让用户自己点选？
   我建议 (a) 自动挑 + 也可以再手动改，体验最好。

2. **功能 3 替换后**：要不要**自动重新生成试穿效果图**？（建议：先更新搭配展示，用户点"生成效果图"再生成，避免每次都等几十秒）

3. **功能 2 城市**：除了自动定位，要不要也保留**手动选城市**的入口（下拉或搜索）？

确认这 3 点后，我按「功能 1 → 2 → 4 → 3」的顺序开始开发（3 最复杂放最后）。
