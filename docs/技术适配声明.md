# 易搭技术适配声明

## 项目形态

- 当前是移动端优先的 H5 AI 穿搭助手，已完成衣柜导入、自动商品图、单品标签、三套推荐和个人效果图的核心闭环。
- 现有技术栈为 React 19 + TypeScript + vinext/Vite + Cloudflare Worker，D1 存结构化数据，R2 存原图、商品图和生成图。
- 现有项目包含 `.openai/hosting.json`，继续沿用 Sites 的 Cloudflare 能力，不迁移到另一套部署架构。

## 本轮改造原则

1. 保留现有视觉和业务流程，不进行无关的页面重设计、模型替换或数据迁移。
2. 以“用户提交要求 → 获得三套衣柜搭配 → 选中一套 → 生成个人效果图”为本阶段纵向切片。
3. 付费 AI 操作必须有服务端幂等键、持久任务状态与结果缓存，不把业务事实只存在页面内存里。
4. 前端统一经过请求层，表达等待、成功、失败、断线与恢复。
5. 真实模型调用只用于最终验收。常规开发与回归不自动发起付费生成，避免重复扣费。

## 技术选择与理由

- **D1 任务表**：保存推荐和效果图任务的所有者、幂等键、状态、请求摘要、结果元数据与错误。这些是用户刷新后仍需恢复的业务状态，不应依赖 `localStorage`。
- **R2 生成结果**：个人穿搭效果图是大对象，由 R2 保存字节，D1 只保存其 key 和类型。
- **客户端请求层**：统一错误解析、超时、中断、幂等键和 202 任务轮询，避免每个页面重复写 `fetch`。
- **当前 owner cookie**：继续用于本阶段私有测试的数据隔离，但它不等于正式用户登录。手机号/微信登录仍是上线前的独立安全阶段。

## 允许的例外

- 动态衣物图片使用原生 `<img>`，因为图片来自需 cookie 所有权校验的 API/R2 流，且 vinext 环境没有完整的 Next Image 优化链路。保留明确尺寸、懒加载与 `alt`，并在 ESLint 中只关闭这一条规则。
- 暂不拆成微服务，当前规模优先保持单应用内部分层，减少运维复杂度。

## 验收门槛

- `npm run lint`、`npm run typecheck`、`npm test`、`npm run build` 全部通过。
- 快速连点生成按钮不会创建重复任务。
- 刷新页面后可恢复最近一次推荐，并可继续查询效果图状态。
- 失败时保留已有衣柜与推荐，页面给出可理解的错误与重试入口。
- 移动端与桌面端的主链路可见、可点、可用键盘操作。
