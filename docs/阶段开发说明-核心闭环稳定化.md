# 阶段开发说明：核心闭环稳定化

## 本阶段目标

在不改变易搭现有产品方向的前提下，把“三套推荐 + 个人效果图”从可演示状态改成可反复测试的稳定闭环，优先解决重复生成、刷新丢状态、长等待无反馈和错误不可恢复。

## 用户故事

- 作为用户，我提交一次穿搭需求后，希望只扣费一次，即使我误触按钮或刷新页面。
- 作为用户，我希望能看到当前在“理解需求”、“生成中”还是“保存结果”。
- 作为用户，我刷新页面后希望继续看到上次的三套方案，或继续等待效果图。
- 作为用户，我在模型失败时希望保留已有内容，并了解下一步怎么做。

## 本阶段范围

### 包含

- 统一客户端 API 请求、超时、错误解析和取消。
- 推荐与个人效果图的 D1 任务记录、幂等键和结果恢复。
- 效果图生成结果保存至 R2，页面不再只持有一个临时 Blob URL。
- 主页关键业务类型、请求逻辑和任务状态拆出。
- 修复当前 ESLint 错误、弹窗可访问性和重要按钮的移动端反馈。

### 不包含

- 更换阿里云模型或重写算法的策略评分。
- 正式手机号/微信登录、计费、会员和配额系统。
- 重做首页视觉、导航信息架构或衣柜识别模型。

## 数据与状态设计

### 任务状态

`pending → running → succeeded | failed`

- `pending`：服务端已接收并固化请求。
- `running`：正在调用模型或下载结果。
- `succeeded`：结果已在 D1/R2 可恢复。
- `failed`：服务端保存了对用户可解释的错误摘要。

### 幂等策略

- 客户端为一次显式生成创建 `Idempotency-Key`。
- 相同 owner、任务类型和 key 只能有一条记录。
- 已成功的任务直接复用结果；执行中返回任务状态；失败后由用户明确点击重试才生成新 key。

## 交互验收

1. 生成按钮提交后立即禁用，文案说明当前状态。
2. 在任务完成前刷新，页面会查询该任务，而不是发起第二次付费请求。
3. 连续快速点击按钮，D1 中只有一条对应任务。
4. 效果图成功后刷新仍可查看，且弹窗有明确关闭按钮、焦点语义和键盘操作。
5. 推荐或效果图失败不清空上一次成功结果。

## 测试计划

- 静态：ESLint、TypeScript、现有 Node 测试。
- 构建：vinext 生产构建。
- 接口：使用假结果或已存任务验证幂等、恢复与错误路径，不自动消耗真实模型配额。
- 界面：验证首页、三套结果、模特照入口、效果图弹窗和手机宽度。
- 真实模型：只在用户确认后各执行一次推荐与效果图烟雾测试。
